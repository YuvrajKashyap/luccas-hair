# Mockup Plan

> Historical planning artifact. For the current shipped state and verified business facts, use `README.md`, `docs/architecture.md`, and `docs/data-provenance.md`.

## Recommended Mockup Order

1. Home desktop.
2. Home mobile.
3. Services desktop.
4. Products desktop.
5. FAQ / Policies desktop.
6. Mobile versions for Services, Products, and FAQ / Policies.

## What Each Page Mockup Must Show

## Home

- First-viewport brand impression.
- Primary Book Appointment CTA.
- Service preview.
- Product preview or secondary product path.
- Trust or brand section using confirmed details only.
- Footer direction.

## Services

- Scan-friendly service structure.
- Space for names, descriptions, prices, and durations, all TBD until confirmed.
- Clear booking path from service comparison.
- Mobile-friendly service grouping.

## Products

- Product catalog or showcase layout.
- Space for product names, images, prices, and descriptions, all TBD until confirmed.
- Product inquiry or future purchase CTA.
- A path back to booking.

## FAQ / Policies

- FAQ and policy structure.
- Booking CTA.
- Product and appointment policy sections.

## Desktop And Mobile Requirements

- Desktop mockups should define navigation, hierarchy, CTA placement, page rhythm, and footer structure.
- Mobile mockups should define sticky booking CTA behavior, menu behavior, card stacking, touch targets, and scan order.
- Booking must stay visible or easy to reach on every core mobile page.
- Text must be readable without crowding the design.
- Product and service cards must remain stable with longer TBD content.

## Asset Extraction Notes

- Save selected mockups in `assets/mockups/`.
- Save visual references in `assets/references/`.
- Save final logo exports in `assets/logo/` only after approval.
- Save confirmed product images in `assets/products/`.
- Track whether each asset is approved, exploratory, or pending.

## One Selected Reference Mockup Per Page Rule

Each MVP page should have one selected reference mockup before implementation. A page can have explorations during Phase 3, but only one direction should become the implementation source.

## Visual Direction Lock Warning

Do not mix visual directions randomly after a page is locked. If a later page needs a different treatment, document the reason and keep the shared brand system consistent.

## Assets To Generate Separately From Mockups

- Final illustrated logo or mascot mark.
- Transparent logo exports.
- Favicon and social preview assets.
- Product photos or product renders.
- Service or environment photography.
- Reusable textures, background images, or hero imagery.
- Any icon set or decorative marks that become part of the final system.
